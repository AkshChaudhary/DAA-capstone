7. ALGORITHM SELECTION

1. Adjacency Matrix
Purpose: Graph representation
Reason: Stores road weights for direct edge lookup.

2. Adjacency List
Purpose: Graph representation
Reason: Stores connected locations and road distances efficiently.

3. Merge Sort
Purpose: Package sorting
Reason: Sorts packages by priority and deadline.

4. Greedy Approach
Purpose: Delivery decisions
Reason: Makes locally best delivery choices at each step.

5. 0/1 Knapsack (Dynamic Programming)
Purpose: Vehicle loading
Reason: Selects valuable packages within vehicle capacity.

6. Dijkstra
Purpose: Shortest path
Reason: Finds shortest routes when road weights are non-negative.

7. Bellman-Ford
Purpose: Negative cycle detection
Reason: Handles negative edge weights and detects reachable negative cycles.

8. Nearest Neighbor Approximation
Purpose: Multiple delivery stops
Reason: Builds an approximate delivery tour by repeatedly selecting the nearest unvisited stop.

8. GRAPH REPRESENTATION OBSERVATION
Adjacency List is space efficient for sparse graphs

3. PERFORMANCE ANALYSIS
Dijkstra uses O(V^2 + E) time with the current array-based vertex selection.
Bellman-Ford uses O(V x E) time.
Merge Sort uses O(n log n) time.
Insertion Sort uses O(n^2) worst-case time.
0/1 Knapsack uses O(n x W) time and space with the current DP table.
Nearest Neighbor repeatedly calls Dijkstra to choose delivery stops.

4. OPTIMIZATION SUGGESTIONS
1. Use a Min Heap or Priority Queue for Dijkstra.
2. Use an efficient adjacency list for sparse graphs.
3. Use Merge Sort instead of Insertion Sort for large package datasets.
4. Use a one-dimensional DP array to reduce Knapsack memory usage.
5. Avoid repeated shortest path calculations when cached distances can be reused.
6. Use larger and realistic datasets for further testing.
